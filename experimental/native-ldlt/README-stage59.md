# LIS BUCKLE – stage 59 / candidate patch 48

Standalone C11 dense reference prototype continuing stage 58. No LIS source or CCX matrix is included. No changes to LIS ABI, no publication to GitHub. No BLAS/OpenBLAS/LAPACK.

## Implementation
`p59_factorize` in `bk_ldlt.c` uses the classical lower Bunch–Kaufman partial pivoting rule on the full active Schur complement, alpha=(1+sqrt(17))/8. It preserves the original p58 entry point for comparison. For column k let lambda be its largest off-diagonal magnitude, r the first maximizing index, sigma the largest off-diagonal magnitude in row r. The four decisions are: current scalar if |akk|>=alpha*lambda; current scalar if |akk|>=alpha*lambda*(lambda/sigma); alternative scalar at r if |arr|>=alpha*sigma; otherwise pair (k,r). The ratio form avoids squaring a large lambda. Zero active column is rejected. The implementation is independent C arithmetic, with scaled block inversion, long double intermediate arithmetic and finite/range checks.

The chosen pivot must be in the current panel and swaps must preserve previous panel membership. A blocked choice returns P58_NO_PIVOT; there is no search fallback and no delayed pivot yet. Prior L entries and factor-to-original permutation are updated on swaps. Nonzero entries outside symbolic L are rejected. Existing p56 packed factor, transactional adapter and p57 cache are reused. Cache stores factors, not p59 statistics; callers must include algorithm/configuration/matrix identity in the cache key.

`max_growth=0` disables growth rejection; a finite value >=1 enables rejection (P59_GROWTH). Growth is max absolute entry across original matrix and stored active Schur complements divided by max absolute original entry. Multiplier statistics are measured, not bounded by this algorithm. Statistics and factor slot update only on success. Caller can set max_n to bound dense workspace. As in stage 58, memory O(n^2), time O(n^3); not suitable for the 152592 DOF CCX matrix. Classical Bunch–Kaufman does not guarantee a uniform bound on multipliers; the observed maxima are specific to the tests. Some nonsingular matrices may be rejected due to symbolic restrictions, arithmetic or growth cap. No MPI/ABI/full LIS/CCX benchmarks.

## Tests
`make stage59-check` builds and executes all stages 55–59 with GCC and Clang ASan+UBSan. `make bk` and `make bk-sanitize` run the new suite only. `make clean` removes binaries. Logs are in test-results.txt. 648 new checks: 600 deterministic random symmetric matrices of sizes 3–16 (some with zero diagonal), scales 1e-100, 1, 1e100; 30 cache round trips; 18 targeted checks including all pivot choices, growth rollback, exact growth limit, symbolic restrictions and alternate scalar rescue. Reconstruction and solve checks use independent matrix multiplication with long double accumulation. Solve acceptance is based on scaled backward error, not forward error; a small backward error does not prove a well-conditioned system. The random suite also ran stage58 on the same 600 matrices: both completed 600/600. One targeted matrix is rejected by stage58 but solved by stage59. No claim of general superiority or measured speedup.

2301/2301 checks in normal build and separately 2301/2301 with sanitizers. New tests: maximum scaled backward error 2.889e-16; max absolute forward error 4.076e-13. Random-suite pivot counts: direct 2393, secondary 191, alternative 776, pair 1164, swaps 1660. Maximum observed growth 9.357401, multiplier 5.313954 (random suite only). `ldd` output in log confirms no BLAS/LAPACK linkage on tested binary.

Reference for mathematical rule: Nicholas J. Higham, Stability of the diagonal pivoting method with partial pivoting, https://eprints.maths.manchester.ac.uk/344/1/29037.pdf ; independent implementation, not a dependency.
